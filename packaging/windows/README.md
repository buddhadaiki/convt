# Windows verification installer

## Windows 11 main menu and logo

The Windows submenu offers the quick conversions picked in Settings → Menu or
with `convt menu`, then a final **Mais** command. Mais opens Quick convert with
the selection and every compatible target, without starting a conversion. The
menu lists only filter the quick formats; the installer's finish page decides
whether the menu appears.

Installer revision `0.3.5` includes `identity/AppxManifest.xml`, its lifecycle
helper and three logo PNGs. On Windows 11 with Developer Mode already enabled,
MSI registers `Convt.Desktop` with the installed directory as external content.
The COM class uses an STA surrogate to expose the command in the main menu.
The current helper requires actual out-of-process `IExplorerCommand` activation,
in addition to checking registration and the external location, before it removes
the owned classic verb to avoid
duplicates. Windows 10 and machines without Developer Mode retain the classic
menu. No policy, certificate trust or Developer Mode setting is changed. The
helpers run with a process-scoped `-ExecutionPolicy Bypass`, because the
Windows client default (Restricted) refuses every `-File` script and would fail
both install and uninstall; a Group Policy execution policy still overrides it
and needs signed helpers.

Registration and removal run as the installing user with checked errors and
paired rollback. Upgrades snapshot the validated previous identity before
Windows Installer removes the old payload inside its transaction. The embedded
helper transfers that identity to the new installation; unrelated identities
fail closed. A guarded backup of the seven package entrypoint/manifest/logo
files lets rollback register the previous identity before MSI restores the
remaining runtime files. Restores check hashes and never overwrite divergent
files. The early `RemoveExistingProducts` action precedes every in-script
custom action, including the rollback action.
Commit actions only discard recovery files: cleanup errors are logged without
rolling back a successful installation using a partially removed backup.
Final-page configuration uses a new transaction GUID for each invocation, so
its compensation cannot roll back an already committed MSI upgrade. A logged
cleanup failure may leave a validated lifecycle journal and block later
maintenance. Resolve the file lock or review preserved foreign content, then
run the matching embedded finish helper's `Commit` with the original transaction
GUID and installation root. Never use `Rollback` for a completed installation.
See [Explorer integration](../../integrations/windows/README.md) for validation
and the current signed-distribution boundary.

The icon is the convt mark from [the brand](../../design-assets/brand/README.md)
on the same dark tile as `packaging/linux/convt.svg`, with the tile filling the
canvas as Windows icons do. `convt-icon.svg` is the source; `brand_assets.py`
renders `convt.ico` (16 to 256 px, each size drawn from the vector) and the
three identity logos in `Assets/` with a built CLI:

```powershell
python packaging/windows/brand_assets.py --convt target/debug/convt.exe
```

Cargo embeds the icon, while
`prepare_app.ps1` merges the package identity into GPUI's existing PE manifest
with the Windows SDK's `mt.exe`, preserving DPI and compatibility settings.
This step precedes signing and is also run by `installer.ps1`. The identity
assets are generated by `brand_assets.py` and staged by `prepare_identity.py`.

```powershell
./packaging/windows/installer.ps1 -InstallerVersion 0.3.5 -WixDll C:\path\to\wix.dll
```

The MSI's registration can be checked headlessly with `explorer-probe --modern`;
an actual Explorer right-click is a separate visual check.

Revision `0.3.2` predates the activation guard. On the local verification machine,
its registration succeeded but COM activation returned `0x80070005`, leaving
neither menu visible. The classic registration was restored. Revision `0.3.3`
was then installed successfully into the fresh external-content directory
`%LOCALAPPDATA%\Programs\convt-v0.3.3`; the installed surrogate returned the
expected JPEG/WebP submenu, and the user confirmed the Windows 11 main-menu
entry on 2026-10-13. Settings were preserved. The previous root had Appx-added
directory permissions but private binary permissions after rollback; normal
deployment into a fresh root propagated permissions without a manual ACL edit.
Registration success alone is not proof that the Explorer command works.

For the same recovery path, use the validated installer with an explicit fresh
directory; do not reuse an existing directory with the failed deployment state:

```powershell
$msi = (Resolve-Path './convt-0.3.3-windows-x86_64.msi').Path
$destination = Join-Path $env:LOCALAPPDATA 'Programs\convt-v0.3.3'
Start-Process msiexec.exe -Wait -ArgumentList @('/i', ('"' + $msi + '"'), ('INSTALLFOLDER="' + $destination + '"'))
```

At that recovery point, `0.3.3` reported installed and the old `0.3.2` reported
`ADVERTISED` after Windows Installer rollback errors. Its residual metadata and
old directory were preserved. Do not treat this recovery as proof of a clean
uninstallation of the previous revision.

The subsequent menu update was verified and installed as revision `0.3.4`
into `%LOCALAPPDATA%\Programs\convt-v0.3.4` after removing the validated `0.3.3`
identity with its installed helper. The `0.3.3` MSI is now absent and `0.3.4`
is installed. The installed modern COM probe returned MOV/WebM/MKV/GIF/Mais
for MP4 and JPEG/WebP/Mais for PNG. An isolated capture stub verified that
Mais forwards the selection without a target or automatic conversion; headless
GPUI tests verified Quick convert and MP3 selection. Real MP4-to-GIF and MP3
conversions were inspected. No live app GUI was launched for those checks.

Revision `0.3.5` was tested with the single Quick convert startup. The finish
page was confirmed in an isolated native MSI fixture; the installed production
DLL's Configure action passed all four menu/desktop choices headlessly. The
installed modern COM command returned JPEG/WebP/Mais for PNG and
MOV/WebM/MKV/GIF/Mais for MP4. A deliberate post-Apply failure restored the previous Appx identity,
all 76 previous files byte-for-byte, and unchanged app settings. On the local
Windows 11 build 26300.9550, Windows Installer subsequently failed to restore
its own old product metadata (errors 1401/1406, system errors 5/1307), leaving
the old MSI advertised. Full MSI metadata rollback is therefore not verified on
that host. SecureRepair refused silent repair with 1602. After explicit user
authorization, removing the advertised old product and installing into
`%LOCALAPPDATA%\Programs\convt-v0.3.5-r1` succeeded with status 0 and installed
product state 5. No registry permissions, policies or certificate trust changed.
Preserve user data and verify both product state and Appx registration after
recovery; restored files alone do not prove a registered MSI installation.

## Build

Run in a Windows x64 checkout with Rust 1.95.0, Visual Studio 2019, 2022 or 2026 C++ build tools (including CMake), Git for Windows, Python 3 and the .NET SDK. The scripts use only user-owned build directories. Git supplies patch and Perl for the codec builds; Strawberry Perl's `patch.exe` is refused (it asserts on the x265 debian series).

```powershell
$env:SOURCE_DATE_EPOCH = '1791244800'
./packaging/windows/build.ps1 -VerificationOnly
./packaging/windows/installer.ps1
```

The MSI shows native progress and then an **O convt está pronto** page, each
headed by the app icon. On a fresh installation, the right-click menu and
**Abrir o convt agora** are checked and the desktop shortcut is unchecked.
**Concluir** applies the choices, opens the app when asked, and closes the
installer; the launch choice is UI-only and never stored. Failed configuration
keeps the page open and reports the error. Previously saved installer choices
are reused on repair/upgrade. They live in the user's
`Software\Convt\InstallerOptions` registry key, separate from app settings,
presets and history. A desktop shortcut is created or removed only when it
belongs to the validated convt installation; foreign shortcuts are preserved.

For quiet installation, pass `CONVT_CONTEXT_MENU=1` (or `0`) and
`CONVT_DESKTOP_SHORTCUT=1` (or `0`) to select the same options. Quiet mode does
not open the app. For diagnostics, run
`msiexec /i C:\absolute\path\convt.msi /L*v C:\absolute\path\install.log`;
Windows Installer status 0 indicates success.

The native build applies `libde265-msvc-scan-init.patch`: MSVC 19.51 on x64 can miscompile the scan-table initialization loop with `/O2`, causing intermittent HEIF startup crashes or incomplete tables. The workaround disables optimization only for that startup routine on the affected compiler; decoding routines stay optimized. `build-native.ps1` also runs `native-scan-test` through CMake/CTest: each of two fresh processes checks all 4,095 base entries and 4,080 derived positions against an independent reference, with caller home space set to 0 and 64. This detects both a crash and an initialization that silently returns incomplete tables. `build.ps1` runs `python packaging/windows/verify-native.py packaging/out/windows/payload` before accepting the runtime. This checks HEIF load/init and the packaged CLI's HEIF availability in fresh processes, without installing or launching the GUI. Pixel conversion checks and a real app launch remain separate validation.

For a partial Windows SDK installation, `build.ps1 -VerificationOnly -WindowsSdkInclude C:\path\to\Include\10.0.26100.0` uses a complete, restored SDK include tree with the existing x64 MSVC tools and SDK libraries. This selects Visual Studio's bundled Ninja for the native codecs; no system SDK files are changed. `installer.ps1` accepts the same `-WindowsSdkInclude` option for its embedded x64 C++ custom-action DLL. If only a .NET runtime is available, `installer.ps1 -WixDll C:\path\to\wix\tools\net6.0\any\wix.dll` runs an already-restored WiX NuGet package without installing a .NET tool. Its version must still match the 6.0.2 pin.

The installer version defaults to the Cargo workspace version. For a packaging or native-runtime repair without changing the Rust binaries' version, use `installer.ps1 -InstallerVersion 0.3.1` after rebuilding the repaired runtime payload. This authors MSI ProductVersion 0.3.1 and writes `convt-0.3.1-windows-x86_64.msi`, preserving the existing 0.3.0 MSI. It keeps the same UpgradeCode so the revised installer can replace 0.3.0 as a major upgrade; it does not change app/CLI 0.3.0 or the document pack's name/hash. An MSI version must contain exactly three numeric components, limited to 255, 255 and 65535. Rebuilding a different ProductCode with the same ProductVersion can leave two products installed, so increment the installer version for a revised delivery.

`build.ps1` verifies every downloaded or cached archive against `inputs.lock.json`, builds the patched codecs, repackages the official LibreOffice MSI, and compiles convt with that document archive's digest and GitHub release URL. It writes `packaging/out/windows/payload` (runtime files only) and `packaging/out/windows/convt-<version>-windows-x86_64-documents.tar.gz` plus `.sha256` beside it. An existing payload is refused; move the previous owned `packaging/out/windows` directory aside before rebuilding. `installer.ps1` stages the runtime harvest, installs WiX 6.0.2 into the checkout's cache, and produces a per-user MSI under `packaging/out/windows`. The harvest refuses the document pack, codec source trees, PDBs, `.lib` files and headers. `python packaging/windows/stage_payload.py` is the allowlist; `packaging/windows/smoke.ps1` extracts the MSI, converts a generated PNG and MP4, installs the sibling document pack, converts a Word file to PDF, and fails if `convt-app.exe` does not stay running. With `-AppExe` it only checks PE subsystems and the Start-menu shortcut.

The MSI installs into `%LOCALAPPDATA%\Programs\convt`, adds a Start menu shortcut to `convt-app.exe`, and registers `convt://` under the current user's `Software\Classes\convt` key. The protocol opens that GUI executable with one quoted URL argument, so the browser can hand desktop sign-in (`convt://auth`) and license keys (`convt://activate`) back to the app; the smoke test installs the MSI, opens a link, checks that it starts the installed app, and uninstalls it again. Outside CI it skips that step when convt is already installed for the user, so a local run never replaces your copy. It also installs `convt_shell.dll` and registers its x64 in-process COM class and file verb in HKCU, adding **Convert with convt** to the classic Explorer menu (Windows 11: **Show more options**). The installer's finish page chooses whether it appears; Settings → Menu or `convt menu` picks the formats it offers. The Windows 11 main menu uses an external-location identity when Developer Mode is already enabled; see the modern-menu section below. See [Explorer integration](../../integrations/windows/README.md). The app binary is a Windows GUI program: launching it must not open a console, and conversion children (FFmpeg, LibreOffice) start with `CREATE_NO_WINDOW`. `convt.exe` stays a console CLI. After a payload build, `./packaging/windows/smoke.ps1 -AppExe packaging/out/windows/payload/convt-app.exe` checks those PE subsystems and the shortcut target. It needs no machine-wide LibreOffice or codec installation. Images, SVG, PDF, video and audio engines find their dependencies beside the installed executable. Document support uses the same on-demand pack as Mac and Linux: Quick convert shows a Download card, and `convt pack install documents` fetches `convt-<version>-windows-x86_64-documents.tar.gz` from the GitHub release, then verifies the compiled SHA-256. A local proof can still pass `--source file:///absolute/path/documents.tar.gz --sha256 <compiled-digest>`. Pack removal leaves a system LibreOffice untouched. Uninstalling the MSI removes its payload, shortcut and authored protocol/Explorer registration and preserves user data.

`python -B -m unittest discover -s packaging/windows -p 'test_*.py' -v` runs the packaging tests. To include the protocol and Explorer registration tests on Windows, set `CONVT_TEST_WIX_DLL` to WiX 6.0.2's `wix.dll` and optionally `CONVT_TEST_DOTNET` to `dotnet.exe`. Those tests compile a temporary MSI and inspect its registry/component/file tables and URL argument boundaries without installing it. The payload stager refuses a missing `convt_shell.dll`. Build and run the `explorer-probe` example to check the real DLL's COM submenu against the adjacent CLI without opening Explorer or invoking the app. Installation, a real Explorer right-click and a browser sign-in round trip remain separate checks.

The artifact is unsigned. Public GitHub Release still builds with `-VerificationOnly` and may attach that unsigned per-user MSI for /download; `inputs.lock.json` keeps `distribution_ready=false` until FFmpeg/PDFium corresponding-source is collected. Do not treat `-VerificationOnly` as publication clearance. See [the licence inventory](../../docs/licence-inventory.md). Signing remains P11; distribution of the modern menu outside Developer Mode still needs a signed identity package.
